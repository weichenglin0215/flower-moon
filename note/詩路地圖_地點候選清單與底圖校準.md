### 1.2 投影假設
高德地圖與 Google/Bing 等主流網頁地圖一樣，採用 **Web Mercator（球面墨卡托）投影**。這個投影有個好處：經度（lng）與像素 x 呈**線性關係**，緯度（lat）則需先轉換成「墨卡托 y」（`mercY = ln(tan(π/4 + lat/2))`，lat 為弧度）才會呈線性關係，且 x 和 y 使用**同一個縮放係數**。這代表只要抓到 3～4 個地理位置明確的參考點，就能反推出整張圖的座標公式。

> 註：高德使用 GCJ-02（火星座標）而非國際通用的 WGS-84，兩者在中國大陸的偏移量約在 50～700 公尺之間。這張圖是全國縮覽視角（每像素代表數公里），這個偏移量完全不影響肉眼可見的城市級定位，可以忽略。

### 1.4 換算公式
用最小平方法把 4 個參考點回歸成統一的線性公式（x／y 共用同一個縮放係數 1652，符合 Web Mercator 應有的特性，這也是校準有效的一個交叉驗證）：

```js
function geoToPixel(lat, lng) {
  const RAD = Math.PI / 180;
  const A = 1652;
  const x = 28.836 * lng - 2033.6;
  const mercY = Math.log(Math.tan(Math.PI / 4 + (lat * RAD) / 2));
  const y = -A * mercY + 1867.9;
  return { x: Math.round(x), y: Math.round(y) };
}
```

### 1.6 已知誤差與後續建議
- 讀取像素座標時人眼判讀誤差約 ±20～30px（換算約 ±0.7～1 度，對應地面約 ±80～110 公里）。對「一張全國縮覽的暫代底圖上標一個城市級圓點」來說是可接受的精度。
- **等底圖換成手繪地圖時，這組公式必須重新校準**——手繪圖的比例、留白、變形程度都會不同。屆時只要在新圖上重新讀 3～4 個好認的參考點（建議固定用北京、西安、成都、廣州、上海這幾個大家都會畫在對的位置的城市），重跑一次同樣的最小平方法即可，不需要重新設計方法論。
- 建議正式寫進 `map.js` 時，把 `geoToPixel()` 獨立成一個小工具函式、參數（A、B、C 三個常數）集中放在檔案頂端一個地方，方便日後換圖只改三個數字。

## 二、地點候選清單（63 首 rating ≥ 6 的詩詞）

### 2.1 欄位說明
- **確定性**：
  - ✅明寫 = 詩題或詩句直接寫出地名
  - 🟡傳統箋注 = 歷代註家/學界普遍認定的寫作背景，但非詩中明寫
  - 🔶延伸連結 = 詩詞課本式的情感延伸（如故鄉、旅圖），非史學定論，UI 上應以不同視覺樣式呈現，明確告知玩家這是「延伸」而非「詩中實寫」
  - ⚠️學界有爭議 = 多地互爭、無定論
- **像素座標**：套用上面 1.4 的公式，直接算出來的 `(x, y)`，可作為在暫代底圖上放置標記的初始座標（換底圖後需重算）。

## 三、需要你確認的幾個判斷

以下幾點我做了「編輯判斷」，麻煩你特別看一下同不同意：

1. **〈清明〉的杏花村**：我標了安徽池州（杜牧任地），但這是史學界公認的**爭議地點**（山西汾陽也自稱是正主）。建議 UI 上用「⚠️」樣式並在彈窗文字裡誠實寫「地點傳說不一，此為其中一說」，而不是當作定論呈現。
2. **〈靜夜思〉〈九月九日憶山東兄弟〉〈雜詩〉〈遊子吟〉這類「故鄉延伸」標記**：這是你一開始就期待的「深度連結」玩法核心，但也是最容易被較真玩家挑戰「這不是詩裡寫的地方」的部分。我在關係欄位標成「故鄉／🔶延伸連結」，建議這類標記在地圖上用跟「實景」不同的視覺記號（例如虛線圖釘 vs 實心圖釘），從介面設計上就先誠實區分開來。
3. **10~11 首「建議不標點」的詩**：這代表 rating 6~7 共 63 首中，實際能上圖的約 52 首、62 個地點。若你希望這批一定要湊滿數量，我可以再想辦法找更迂迴的延伸連結（例如按作者生平硬掛一個地點），但我不建議這樣做——寧可誠實地少幾個點。
